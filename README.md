## 🌟 Что такое Aster

**Aster** — Android-агент и исполнительный слой управления устройством, построенный вокруг Android Accessibility и Model Context Protocol (MCP).

Главная задача Aster — дать ИИ возможность надёжно работать с реальным интерфейсом телефона, а не просто выполнять слепые клики по координатам.

### Основные возможности

- **Наблюдение** — иерархия Accessibility, снимки экрана, окна, состояние приложений и события.
- **Снимок интерфейса** — ограниченное адресное представление текущего UI.
- **Стабильные ссылки на элементы** — описание целевого элемента вместо использования живого `AccessibilityNodeInfo` как постоянного идентификатора.
- **Повторное разрешение элемента** — поиск актуального узла непосредственно перед выполнением действия.
- **Проверка перед действием** — подтверждение, что найденный узел действительно соответствует ожидаемой цели.
- **Действия** — нажатие, долгое нажатие, ввод текста, прокрутка, свайп и системные действия Android.
- **Синхронизация по событиям** — ожидание реальных изменений Accessibility/состояния вместо зависимости только от фиксированных задержек.
- **Несколько окон** — поддержка окон приложения, системы, диалогов, разделённого экрана и клавиатуры.
- **Поддержка Jetpack Compose** — использование `testTag`, ID, текста, описания, роли, класса и других признаков.
- **Безопасная обработка устаревших ссылок** — отсутствующая или несовпадающая ссылка отклоняется вместо опасного действия над другим элементом.
- **Защитные механизмы** — аварийная остановка STOP и ограничения политики пакетов.
- **MCP** — предоставление возможностей Android ИИ-агентам через Model Context Protocol.

## 🔄 Протокол Hands

Надёжный цикл выполнения:

```text
НАБЛЮДЕНИЕ
     ↓
СНИМОК
     ↓
ПОИСК ЦЕЛИ
     ↓
ПРОВЕРКА ЦЕЛИ И СОСТОЯНИЯ
     ↓
ДЕЙСТВИЕ
     ↓
ОЖИДАНИЕ ИЗМЕНЕНИЯ СОСТОЯНИЯ
     ↓
ПРОВЕРКА РЕЗУЛЬТАТА
     ↓
повтор до достижения цели / STOP
```

Если ссылка устарела, отсутствует, неоднозначна или больше не соответствует интерфейсу:

```text
УСТАРЕЛА / НЕ СОВПАДАЕТ
          ↓
      НАБЛЮДЕНИЕ
          ↓
    НОВЫЙ СНИМОК
          ↓
      НОВЫЙ ПОИСК
          ↓
       ПРОВЕРКА
          ↓
       ДЕЙСТВИЕ
```

### Ключевое правило

**Живой объект `AccessibilityNodeInfo` нельзя считать постоянным ID элемента интерфейса.**

Узел Android может быть уничтожен и создан заново после обновления UI, навигации, появления диалога или изменения окна. Поэтому агент должен хранить описание целевого элемента и заново разрешать его относительно текущего дерева Accessibility.

## 🧩 Связь с OX2 и Светланой

Aster является **эталонным источником проверенных механизмов и исполнительным слоем**, а не заменой архитектуры OX2.

Целевая архитектура:

```text
                 ┌──────────────────────┐
                 │       СВЕТЛАНА       │
                 │   лицо + голос + чат │
                 └──────────┬───────────┘
                            │
                    ЕДИНЫЙ COMMAND BUS
                            │
                 ┌──────────▼───────────┐
                 │      OX2 AGENT       │
                 │ планирование / loop  │
                 │ состояние / память   │
                 └──────────┬───────────┘
                            │
                 ┌──────────▼───────────┐
                 │     HANDS ENGINE     │
                 │ наблюдать → действ.  │
                 │ проверить → повторить│
                 └──────────┬───────────┘
                            │
          ┌─────────────────┼─────────────────┐
          ▼                 ▼                 ▼
     Accessibility       Shell/Termux       Files
       управление UI       команды           файлы
                            │
                            ▼
                         Android
```

### Правила интеграции

1. **Светлана остаётся пользовательским ИИ-ассистентом** — лицо, голос и чат не заменяются интерфейсом Aster.
2. **Чат и голос используют единый Command Bus**, поэтому обе формы общения выполняют одни и те же команды.
3. **OX2 остаётся уровнем планирования, loop, состояния и памяти.**
4. **Aster/Hands отвечает за надёжное наблюдение и выполнение действий на Android.**
5. **Код Aster нельзя копировать вслепую.** Используются только доказанно полезные паттерны с сохранением контрактов и forensic-gates OX2.
6. Предпочтительный путь: **наблюдать → разрешить → проверить → действовать → проверить**.
7. **STOP должен быть доступен всегда.** Разрушительные, финансовые и чувствительные к приватности операции требуют дополнительных ограничений и подтверждений.

## 🧠 Почему нужны снимки и повторное разрешение

Узлы Android Accessibility являются живыми объектами фреймворка. После изменения интерфейса они могут исчезнуть или быть пересозданы.

Поэтому надёжный агент хранит не сам объект, а набор признаков целевого элемента:

- ID ресурса или View ID;
- текст;
- `contentDescription`;
- агрегированную подпись;
- Compose `testTag`;
- роль и класс;
- координаты границ;
- идентификатор окна;
- структурный путь, если он доступен.

Непосредственно перед действием элемент разрешается заново и проверяется. Это предотвращает ситуацию, когда старый объект указывает уже не на тот элемент.

## 🔬 Требования forensic-проверки OX2 Hands

Интеграция считается успешной только после подтверждения реальными runtime-доказательствами. **Зелёный CI сам по себе не означает PASS.**

Необходимые признаки:

- `ACCESSIBILITY_SERVICE_ENABLED=PASS`
- `HANDS_SMOKE_START`
- `HANDS_UI_OBSERVE_RESULT` с `nodes>0`
- `HANDS_UI_ACT_RESULT` с успешным действием
- `PASS:REAL_ACCESSIBILITY_TAP_VERIFIED`
- ожидаемый пакет находится на переднем плане
- отсутствуют `AndroidRuntime`, `FATAL EXCEPTION` и `ReactNativeJS`
- присутствует артефакт `hands-logcat.txt`

Только наличие полного подтверждённого runtime-цикла позволяет объявить Hands действительно прошедшим проверку.

## 🛡️ Безопасность

Aster предоставляет ИИ привилегированный доступ к Android-устройству. Поэтому исполнительный слой должен рассматриваться как чувствительная часть системы.

Рекомендуемые ограничения:

- видимая аварийная кнопка **STOP**;
- отказ от действия при устаревшей или неоднозначной ссылке;
- ограничения по пакетам приложений;
- подтверждение разрушительных, финансовых и чувствительных к приватности действий;
- принцип минимально необходимых разрешений Android;
- журналирование выполнения;
- проверка результата после каждого значимого действия.

## 📦 Структура проекта

Основные части Aster:

- `apps/android` — Android-приложение, Accessibility Service и системные механизмы управления;
- `mcp` — MCP-сервер и инструменты взаимодействия с устройством;
- `mcp/dashboard` — веб-панель управления и наблюдения;
- `skill` — интеграционные материалы для ИИ-агентов.

Технические названия каталогов, API, классов и инструментов намеренно сохраняются в оригинальном виде, чтобы разработчик мог непосредственно найти их в исходном коде.
